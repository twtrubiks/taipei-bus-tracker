## Context

eBus `POST /EBus/GetStopDyns` 每站回傳的結構（實測 299 去程，59 站）：

```json
{"sn": 12, "eta": 3, "bi": null, "bo": [{"bn": "KKB-1789", ...}], ...}
```

| 欄位 | 語意 |
|---|---|
| `bi` (bus in) | 車輛目前停靠在第 `sn` 站 |
| `bo` (bus out) | 車輛已駛離第 `sn` 站，正在往第 `sn+1` 站的路上 |

`internal/ebus/convert.go` 的 `EBusStopDynRaw` 兩個欄位都有解析，但 `convertETAs` 只迴圈 `s.BI`，`s.BO` 從未被讀取。同一份快照裡 17 個有車的站中有 9 站的車只在 `bo`，這些車在 UI 上完全不存在。

TDX 側的 `EstimatedTimeOfArrival` endpoint 只有 `PlateNumb`，沒有進站／離站的語意區分，因此 TDX 的 `DepartedBuses` 恆為空。

## Goals / Non-Goals

**Goals:**
- 上游回報的每一台車都要出現在畫面上，不因為在站間而消失
- 車輛位置以視覺呈現（站上 vs 站間），不需要逐行讀文字推測
- TDX 與 eBus 共用同一個資料模型與同一份前端版型，TDX 只是資料較少

**Non-Goals:**
- 不引入 TDX `RealTimeNearStop`（`A2EventType` 0=離站／1=進站）。語意雖與 `bi`/`bo` 相同，但每次輪詢要多打一次 TDX，在 rate limit 壓力下不划算——先讓 eBus 版本上線看效果
- 不改 ETA 三級狀態、輪詢間隔、快取 TTL、fallback 策略
- 不改首頁收藏卡片的版型（單站顯示，沒有「站間」的概念）
- 不畫地圖

## Decisions

### 1. 新增 `departedBuses` 而非把 `bo` 併入 `buses`

**選擇**: `StopETA` 有兩個陣列——`buses`（停靠在該站）與 `departedBuses`（已駛離該站）。

**替代方案**: 把 `bo` 直接 append 進 `buses`。

**理由**: 併入的話車號雖然不再消失，但會出現在錯誤的位置——一台剛離開第 13 站的車會被畫成「停在第 13 站」，而它其實已經在 13→14 之間。位置資訊是這次要呈現的重點，合併等於在修一個 bug 的同時製造另一個誤導。分成兩個欄位讓消費端自行決定要不要區分，首頁那種不區分的版型只讀 `buses` 即可，行為不變。

### 2. 離站車輛掛在「來源站」而非「目的站」

**選擇**: `bo` 屬於第 N 站的 `departedBuses`，前端把它畫在 N 與 N+1 之間的連線上。

**替代方案**: 轉換時把 `bo` 移到第 N+1 站，當作「即將抵達 N+1 的車」。

**理由**: 上游的事實是「這台車離開了 N 站」，它下一個停靠點不必然是 N+1（可能有站不停靠、或已是末站）。搬移等於在資料層做推論，推錯了無從察覺；保留原始歸屬，由前端在版型上表達「介於兩站之間」，資料層只忠實轉述。末站的 `bo` 沒有下一段連線可畫，前端直接畫在末站節點下方。

### 3. 時間軸版型放在 `StopList`，不新增頁面

**選擇**: 改寫既有 `StopList` 的版型，左側時間軸（節點 + 連線），車輛圖示疊在節點或連線上。

**理由**: 站間的車需要「兩站之間有實體空間」才畫得下，原本的純列表沒有這個空間。時間軸是最小的改動——每個 `<li>` 內部加一條垂直線與一個節點，站間車輛渲染在該 `<li>` 的連線段上，不需要改變資料流或元件邊界。

### 4. 圖示用 inline SVG，不引入 icon 套件

**選擇**: `BusMarker.tsx` 內嵌一個公車 SVG，隨 `currentColor` 變色。

**理由**: 只需要一個圖示，引入 icon 套件是為了一個檔案付出整包 bundle 與一個新相依。inline SVG 也讓深色模式直接沿用既有的文字顏色 token。

## Risks / Trade-offs

- **`bo` 的語意來自觀測而非官方文件**：eBus 沒有公開 API 文件，`bi`/`bo` 的解讀來自實測資料的分佈（車號從第 N 站的 `bi` 消失後出現在 N 的 `bo`，再出現在 N+1 的 `bi`）。若解讀有誤，最壞情況是車輛畫在相鄰的錯誤位置——仍優於現在整台車消失。
- **同一台車可能同時出現在兩處**：eBus 快照中未觀察到，但若上游同時把某車放進 N 的 `bo` 與 N+1 的 `bi`，畫面會出現兩個圖示。前端不做跨站去重（那需要假設站序連續且資料同一時刻），先如實呈現，實際遇到再處理。
- **列表視覺變重**：時間軸與圖示增加了每列的繪製成本，且本頁每秒重繪一次（既有的倒數機制）。60 站量級對 React 無壓力，若日後有效能問題再對列做 memo。
